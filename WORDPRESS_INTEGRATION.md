# WordPress Booking Integration Contract

The Django HMS does not provide public online booking. Existing WordPress booking remains authoritative for the booking/payment event that occurs on sonogahotels.com. WordPress synchronizes the operational reservation into the HMS.

## Endpoint

```text
POST /api/wordpress/bookings/
```

## Required booking identity

`external_reference` must be the stable unique booking identifier generated by WordPress/the booking plugin. Sending the same reference again updates the existing HMS reservation instead of creating a duplicate.

## New booking payload

```json
{
  "external_reference": "WP-BOOKING-7812",
  "business_unit_code": "HOTEL",
  "room_type_code": "DLX",
  "arrival_date": "2026-08-20",
  "departure_date": "2026-08-23",
  "adults": 2,
  "children": 0,
  "nightly_rate": "50000.00",
  "discount_amount": "0.00",
  "tax_amount": "0.00",
  "status": "CONFIRMED",
  "special_requests": "Late arrival",
  "guest": {
    "first_name": "John",
    "last_name": "Doe",
    "phone": "+2348000000000",
    "email": "john@example.com"
  },
  "payment": {
    "reference": "WP-PAY-9921",
    "external_reference": "gateway-transaction-123",
    "amount": "50000.00",
    "method": "ONLINE"
  }
}
```

## Later updates

The same `external_reference` can be resent when WordPress records:

- confirmation;
- cancellation before check-in;
- date change before check-in;
- an additional payment.

Once the guest is checked in or checked out, WordPress is not allowed to move the HMS operational status backwards. Payments received online after check-in are attached to the active guest folio.

## Signature

When `SONOGA_WORDPRESS_REQUIRE_SIGNATURE=True`, compute HMAC-SHA256 over the exact raw JSON body:

```text
message = unix_timestamp + "." + raw_json_body
signature = HMAC_SHA256(SONOGA_WORDPRESS_API_KEY, message)
```

Headers:

```text
X-Sonoga-Api-Key: <secret>
X-Sonoga-Timestamp: <unix timestamp>
X-Sonoga-Signature: sha256=<signature>
```

Requests outside the configured timestamp tolerance are rejected to reduce replay risk.

## Plugin mapping still required

The final WordPress hook cannot be hard-coded safely until the exact booking plugin used on sonogahotels.com is identified. The provided PHP helper is ready to be called from that plugin's successful-booking and payment-update hooks.

## Connectivity test before booking hooks are enabled

The HMS exposes an authenticated, signed test endpoint:

```text
POST https://manage.sonogahotels.com/api/wordpress/ping/
```

Use `sonoga_hms_ping()` from `deploy/wordpress_webhook_helper.php.example`. A successful response confirms that the shared secret/signature, proxy path, integration user, Hotel business unit and HMS endpoint are reachable without creating a reservation.

Do not connect the actual booking event until this ping succeeds. The final WordPress event hook still depends on the exact booking plugin installed on the site.
